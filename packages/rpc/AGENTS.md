# @ainess/rpc 开发指引

使用示例、公开接口和线协议见[使用手册](README.md)。

- 本包提供固定二进制协议上的 TCP 点对点 RPC。公开入口为 `@ainess/rpc`。应用用 `RpcServer.listen()` 建立监听器，用 `RpcPeer.connect()` 拨号，监听端用 `onPeer` 取得同一连接的另一端。两端的 `RpcPeer` 都可以发起和接收调用。`RpcClient` 是 `RpcPeer` 的别名。业务方法、服务发现、业务对象编码与应用装配由调用方负责。运行时使用 Node.js 原生 API。
- 调用方按字符串方法名调用，用 `request()` 接收单响应，用 `stream()` 接收流式响应。省略请求数据时可直接在方法名后传入选项，处理函数收到长度为 0 的 `Uint8Array`。选项 `input` 提供独立可取消的上传源。处理函数通过 `input.stop()` 只结束上传方向，响应仍可继续。处理函数可用 `peer` 在同一连接上发起反向调用。
- `peer.register({ name, mode, handle })` 注册当前连接的方法，`server.register()` 注册监听器共享的方法。连接专属方法优先于同名共享方法。方法名在各自的注册表内唯一，区分大小写，UTF-8 编码长度为 1 至 255 字节。预注册列表使用相同校验。注销函数立即移除该注册，等待已接收的处理函数与响应流完成清理，可重复调用。同名方法可在旧注册等待清理期间重新注册。
- 帧头定长 12 字节，消息体有独立长度。TCP 解码消费完整帧并保留半包。双方交换版本为 2 的 `HELLO`。`OPEN` 消息体依次包含单字节方法名长度、UTF-8 方法名和请求数据。拨号端发起调用时使用递增的奇数 ID，接入端使用递增的非零偶数 ID，0 保留给连接级帧。连接级短消息和流数据额度分别计算，流数据还受调用级额度限制。收到超长、非法或截断的帧时结束对应连接。
- `listen()` 和 `connect()` 可用 `maxConcurrentCalls` 配置每条连接的入站并发上限，默认 256，可设为 1 至 4096 的整数。`HELLO` 公布该上限，出站调用取本端设置与对端公布值中的较小值。连接窗口仍由同一连接上的调用共享。
- 单调用流式窗口和 TCP 读写高水位均为四个最大帧的总长，窗口按帧头与帧体的总字节数计费。短消息窗口剩余不到四分之三时批量补回。流式额度在消费后累积，达到半窗或可用额度不足一个最大帧时尽快归还，其余情况按 1 毫秒定时器合并更新。`OPEN` 一次编码帧头和帧体，其他小帧合并写入，较大的帧分开提交帧头和帧体。并发小帧可批量发送，发送端受写入背压约束。排队 `DATA` 引用的缓冲区超过计费字节数四倍时，复制到独立缓冲区以限制队列内存占用。
- `listen()` 等待端口就绪，`connect()` 等待协议握手。接入端在握手后和分派首个入站调用前同步执行 `onPeer`。响应流在首次读取时启动，提前退出响应迭代取消调用。`peer.close()` 关闭当前连接并清理其两个方向的调用，`server.close()` 关闭监听和接入连接。关闭操作可重复调用。
- 在根目录运行 `pnpm --filter @ainess/rpc build` 和 `node --test 'packages/rpc/test/*.test.js'` 验证拆帧、真实 TCP 调用和生命周期，再运行 `pnpm test` 验证整个工作区。
